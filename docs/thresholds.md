# 去重阈值标定

## 为什么不能拍一个数

阈值是相似度的分界，而相似度的量纲取决于编码器。同一个 0.85，在词法编码器和在
句子向量模型上代表完全不同的东西：前者对同语言的同义改写只有 0.4 至 0.6，
后者对同一件事的两种说法普遍在 0.8 以上。

所以阈值不是配置项，是标定结果。换编码器、换模型、换语言分布之后都要重跑。

## 标定方法

`npm run calibrate` 用 `src/fixtures/calibration-pairs.ts` 里的标注样本，
对每一对算余弦相似度，按同一事件与不同事件分成两组，看两组能不能分开。

输出包含三部分：每一对的相似度和判定结果、两组的分数区间、以及可直接写入 `.env` 的两个阈值。

取值规则是「宁漏勿误」，两级一起看：

**· DUP_THRESHOLD**

取不同事件组最高分加 0.02。这样保证没有任何一个被标注为「不同事件」的样本会被硬判重，
代价是只有相似度明显高于所有反例的才直接丢弃。

**· GRAY_LOW**

取同一事件组最低分减 0.02。这样保证没有任何一个同一事件会连判定机会都没有。

两者之间就是交给日报阶段裁决的疑似区间。两组完全分得开时两个值会靠拢，中间区间接近空。

退出码 0 表示建议阈值可以直接用（误杀为 0），退出码 1 表示按当前样本取值会把不同事件判重，
需要上调 `DUP_THRESHOLD`。

## 两级阈值

真实数据里两组分布经常有重叠，单阈值无论怎么取都要么误杀要么漏判。所以判定分三段：

**· 相似度达到 DUP_THRESHOLD**

判为重复，直接丢弃，记入 `dropped` 并写明命中的是哪一条。

**· 相似度落在 GRAY_LOW 与 DUP_THRESHOLD 之间**

保留但标记为疑似，交给日报阶段做最后裁决。当前实现是打上 `semantic` 标记，
日报阶段可以据此合并或保留两条。

**· 相似度低于 GRAY_LOW**

正常保留。

**· 同源条目**

阈值再加严 `SAME_SOURCE_MARGIN`。同一家媒体的连载（Rust 1.90 与 1.91）用词天然接近，
不加严会被误判成重复。

## 已知数据

第一版用词法编码器在同样这 10 对样本上实测的结果：

**· 同语言同一事件**

0.837，能判出来。

**· 跨语言同一事件**

0.073 至 0.296，判不出来。英文原文与中文报道共用词很少，词法编码器没有跨语言的
语义概念。

**· 不同事件但同源**

最高 0.667，不会误判。

结论是词法编码器只覆盖同语言近重复，跨语言必须换成真实 embedding 模型。
这组数字也写进了测试：`tests/calibrate.test.ts` 断言词法编码器报告「单阈值不可分」。

换成 bge-m3（本地 Ollama，1024 维）之后重跑同一批样本：

**· 同事件组**

0.936、0.895、0.823、0.816、0.805，最低 0.805。跨语言那四对全部落在这一组里，
说明模型确实把中英文的同一件事拉近了（词法编码器上是 0.073 至 0.296）。

**· 不同事件组**

0.894、0.655、0.602、0.566、0.516，最高 0.894。这个最高分来自
`Rust 1.90 released` 与 `Rust 1.91 released`——相邻版本号本来就极像，
任何向量模型都会给出高分。

**· 结论**

单阈值不可分（0.894 ≥ 0.805），这是常态而不是模型不行。按上面的规则取
`DUP_THRESHOLD=0.914`、`GRAY_LOW=0.785`，在 10 对样本上的效果是：直接判重 1 对、
标为疑似 5 对、直接保留 4 对，**误杀 0 对**。那对 Rust 落在疑似区间，
由日报阶段裁决，不会被直接丢掉。

## 调参之后的观察点

每次运行都会把判重与疑似的明细写进日志。周期性地看两个数：疑似条目明显多于判重条目时，
说明 `GRAY_LOW` 偏低，日报阶段承担了过多判断；判重长期为 0 而人工复核发现了重复时，
说明 `DUP_THRESHOLD` 偏高。
